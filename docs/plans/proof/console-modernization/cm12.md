# CM12 proof: comparison mode

Date: 2026-08-21. Branch: `codex/cm-12-compare` on main @ 7e71726.

## What landed

- `console/src/components/chat/Compare.tsx`: the comparison seam.
  `useCompare` owns the ephemeral compare state (active, 2–4 attached
  models, per-column stream state) and mirrors the single-chat stream
  lifecycle per column: `streamChat` with delta/reasoning callbacks,
  per-column `AbortController`, stats from usage on completion,
  abort-preserves-partials marked `stopped`, error text on failure.
  The request body (minus `model`) is frozen at send so per-column
  retry replays the identical prompt. `CompareView` renders the
  welcome state, the prompt echo, and a responsive column grid
  (1 → 2 → n columns via a `--compare-cols` variable). Column cards
  reuse the CM11 `Markdown`, `ReasoningFold`, and `MetadataLine`
  exports so rich rendering and the stats vocabulary stay identical
  to single chat. Comparisons are never persisted.
- `console/src/components/chat/Composer.tsx`: compare affordances.
  A Compare toggle in the composer bar; attached-model chips with
  remove buttons beside the picker trigger; the trigger becomes
  "Add model (n/4)" and the picker stays open across adds; duplicate
  adds are ignored; send requires 2–4 models; the effort selector is
  hidden in compare (per-column reasoning defaults apply).
- `console/src/routes/chat.tsx`: mode wiring. Entering compare seeds
  the current model as the first chip and detaches the active thread;
  thread open/new exits compare; "Continue with this model" collapses
  the comparison into a new saved conversation holding the prompt and
  the chosen column's full message (stats and reasoning fold intact),
  then regenerates the title.

- `pnpm -C console check` → Vite build + `tsc --noEmit` clean.
- Live against the dev gateway, in Chrome and in the headless
  capture run:
  - Toggle enters compare with the welcome copy ("Pick two to four
    models…", "Comparisons stay on this page and are not saved") and
    the seeded chip ("1/4 models attached").
  - Picker add-mode: stays open across adds, chips appear live, a
    duplicate click on an attached model does not add a second chip.
  - One prompt fanned out across 3 columns: two streamed complete
    markdown answers with reasoning folds, tables with copy
    controls, and full stats lines (`ttft 728ms 1.96s total
    158.4 tok/s ↓36 ↑196 102 reasoning cache miss`); a column routed
    to a credential-less provider showed the live error branch (red
    "Provider credentials are not configured." + mono `failed`).
  - Per-column retry re-ran only the failed column.
  - Per-column stop mid-stream (programmatic click on
    `Stop groq/compound-mini`): that column kept its partial marked
    `stopped` while the neighbor completed a 1–300 count with stats
    `ttft 308ms 3.09s total 430.2 tok/s ↓23 ↑1,198 599 reasoning
    cache miss` — column isolation holds.
  - Continue-with-this-model created a saved conversation with the
    prompt + chosen answer (fold and stats preserved), regenerated
    the title, and exited compare; a follow-up turn answered from
    the seeded history.
  - Chip removal returns the count to "0/4 models attached" with the
    trigger reading "Add model (0/4)".
- `bash scripts/verify-console-modernization.sh` → 19 passed,

## Observed follow-ups (out of CM12 scope)

- The response cache stores empty upstream completions (`↑0`) for
  the full TTL, so a transient empty answer replays on retry.
- A groq daily-token-limit 429 surfaces as an empty 200 stream
  rather than a normalized provider error (`internal/failure` gap).
