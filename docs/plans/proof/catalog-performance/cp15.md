# CP15 — Overhead surfacing

Date: 2026-08-22
Branch: `codex/cp15-overhead-surfacing`

## What shipped

- `usage.Record.TTFTMS` (`ttft_ms,omitempty`): time from request start to the
  first stream event. Only streamed requests carry it. Captured in
  `usageCaptureStream.Read` and persisted in `finalize`.
- `GET /api/v1/admin/metrics` now returns an `overhead` percentile map
  (`p50`, `p95`, `p99`) beside `latency`, computed by the same nearest-rank
  helper over the 24-hour record sample.
- Console Usage page: `overhead` and `TTFT` columns between tokens and
  latency, with hover titles that define each number. Detail panel rows
  "Starport overhead" and "TTFT".
- Console Overview: "Starport overhead p50" stat with a p99 detail line;
  the two latency stats merged into one "Latency p50" stat with a p95
  detail line. Grid stays at six stats.
- Benchmark harness `TestGatewayOverheadBenchmark`
  (`internal/server/controllers/overhead_benchmark_test.go`): 200 requests
  through the real controller → proxy → router pipeline against a mock
  connector that sleeps 20 ms. Reads `x-starport-overhead-ms` from every
  response, computes nearest-rank p50/p99, fails when p99 > 50 ms.
  Env-guarded (`STARPORT_OVERHEAD_BENCH=1`) so `go test ./...` skips it.
- `scripts/benchmark-overhead.sh` runs the harness. Wired into the CI
  release-contract verify block and the AGENTS.md required-evidence list.
- README performance claim paragraph and `docs/PERFORMANCE.md` methodology
  (definition, surfaces, harness, exclusions, local reproduction).
