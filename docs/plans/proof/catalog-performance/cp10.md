# CP10 — Models list traversal

Date: 2026-08-22. Branch: `codex/cp10-models-traversal`.

## What shipped

- `console/src/lib/modelFilter.ts`: author facet (`authorIdsOf` —
  declared authors with an id-prefix fallback), tag facet, and fuzzy
  search. `fuzzyIncludes` accepts a substring or an in-order
  subsequence with separators stripped, so `gptoss120` finds
  `openai/gpt-oss-120b`. Query candidates now cover the canonical id,
  display name, author ids and names, and provider model ids.
- `console/src/routes/models.tsx`: `All authors` and `All tags`
  facet selects with per-option counts alongside the existing
  provider/modality/capability filters; the search input edits a local
  draft and updates the URL after a 200 ms debounce, so the filter
  pass over 422 rows runs once per pause, not per keystroke.
- `console/src/components/models/ModelsTable.tsx`: rows are clickable
  — the id chip links to `/models/:modelId` and the whole row
  navigates on click (inner links and the copy button keep their own
  clicks). Virtualization was already in place via
  `useWindowVirtualizer`.
- `console/src/components/models/FreshnessBar.tsx`: slimmed to one
  line. The inline counters moved into a `details` popover with the
  full generation id, generated-at timestamp, catalog sequence,
  availability revision, completeness, degradation reasons, and the
  manifest-unavailable reason.

## Contract tests (named acceptance cases)

- `modelFilter.test.ts` — author facet (declared authors + prefix
  fallback), tag facet, fuzzy id match (`gpt4o` → `openai/gpt-4o`,
  `llama318b` → `meta/llama-3.1-8b-instruct`, order violations
  rejected), provider-model-id search, `include_reasoning`.
- `ModelsTable.test.tsx` — virtualization smoke: 422 models render a
  bounded DOM (row count > 1 and < 100, `aria-rowcount` 422) inside a
  1 s jsdom frame budget; the id cell links to the detail route.
- Fail-before: the author facet cases fail against the old list —
  `ModelsSearch` had no `author` key and `matches` ignored authors.
