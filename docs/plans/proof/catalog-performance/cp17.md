# CP17 — Failure normalization and cache honesty

Date: 2026-08-22
Branch: `codex/cp17-failure-normalization`

## Root cause

Providers can reject a streaming request after the HTTP 200 response and the
SSE stream are established. Groq delivers the rejection as an
`event: error` frame inside the 200 stream; Gemini emits a
`google.rpc.Status` error object inside the JSON stream body; Anthropic
emits an `error` event; Ollama sets an `error` field on a chunk. The old
stream codecs decoded these payloads into empty `ChatStreamChunk` values or
dropped them. The client received an empty HTTP 200 stream, the request log
recorded a success, and the empty completion was eligible for the response
cache — a provider failure replayed as a cached success. Repro notes:
`cp17-streaming-429-repro.md` (scratch research, summarized here).

## What shipped

Three seams, one contract: a provider rejection is a failure everywhere,
never an empty success.

- **Stream codecs surface in-stream error frames as `*APIError`**
  (`internal/providers/connectors`):
  - `openai_common.go`: the SSE reader now tracks the `event:` name;
    `decodeStreamAPIError` converts an error envelope (or any
    `event: error` payload) into an `*APIError`, with
    `statusFromStreamErrorCode` recovering the HTTP status from the
    provider's type/code markers (rate limit and quota → 429, api key and
    authentication → 401, permission → 403, not found → 404, default 502).
  - `anthropic.go`: `error` events map through
    `anthropicStreamErrorStatus` (invalid_request 400, authentication 401,
    permission 403, not_found 404, rate_limit 429, overloaded 529,
    default 502).
  - `gemini_types.go` + `google_base.go`: `geminiResponse.Error`
    (`google.rpc.Status` shape) returns an `*APIError` with the provider's
    own code when it is a valid HTTP error status.
  - `ollama.go`: a chunk-level `error` string returns an `*APIError` (502).
- **The router reads the first stream event during attempt establishment**
  (`internal/router/execution_adapter.go`): the attempt callback calls
  `stream.Recv()` once inside `TrackUpstream` before declaring the attempt
  healthy. A first-event error takes the same
  `connectors.NormalizeFailure` → attempt-failure path as a non-200
  establishment failure — so it fails over across routes, surfaces the
  normalized HTTP status through the existing `writeError` chain, and the
  request log records the failure kind (via `usageCaptureStream.finalize`).
  An immediate `io.EOF` becomes a retryable `ProviderUnavailable`
  "empty stream" failure. `connectorEventStream` replays the buffered
  first chunk before resuming `Recv`, and the first-token wait is
  attributed to upstream time (excluded from `X-Starport-Overhead-Ms`).
- **The response cache refuses empty completions**
  (`internal/response/cache/repository.go`): `PutChat` returns
  `ErrEmptyResponse` for a completion with no choices, or with zero output
  tokens and no content, reasoning, or tool calls in any choice.
- `internal/providers/connectors/mock.go` gains `SetStreamRecvError` so
  contract tests can model in-stream rejection.
- `scripts/verify-catalog-performance.sh` gains CPV20 (streaming provider
  rejections normalize and empty completions stay uncached).

## Fail-before evidence

Run before the fix, the new contract tests failed in the defect's shape:

- `TestStreamRecvSurfacesEventErrorFrame`,
  `TestStreamRecvSurfacesErrorDataFrame`,
  `TestStreamRecvSurfacesMidStreamErrorFrame`,
  `TestStreamRecvSurfacesUnknownErrorFrame` — failed with
  `Expected nil, but got: &connectors.ChatStreamChunk{...}`: the error
  payload decoded into an empty chunk.
- `TestRouteStreamFailsOverWhenFirstEventIsError`,
  `TestRouteStreamSurfacesFirstEventRateLimit`,
  `TestRouteStreamRejectsEmptyProviderStream` — failed with
  "An error is expected but got nil": the empty stream was a success.
- `internal/response/cache/admission_test.go` failed to build on
  `undefined: ErrEmptyResponse`.

  chunks, the "OK" content delta, `finish_reason: stop`, and `[DONE]`
  (`cp17-stream-live.txt`).

  to `google/gemma-4-26b-a4b-it` hit the provider limit at request 31,
  which returned real HTTP 429 with body
  `{"error":{"message":"The provider rate limit was reached.",

  `status_code: 429`, `error_class: "rate_limit"`.
- Streaming requests to unconfigured or absent offerings return normalized
  401 / 404 before any stream bytes.
