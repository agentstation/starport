# CP16 — Credential resolution evidence

Date: 2026-08-22
Branch: `codex/cp16-credential-evidence`

## Root cause

The original defect (Design Review No. 2 research, baseline-notes.md lines
91-100) was google-ai-studio silently ignoring `GEMINI_API_KEY`: no
configuration, no log line, no failure entry. Investigation for this task
found:

- The resolution gap no longer reproduces. The v0.7.0 Starmap pin (#165)
  fixed the credential contracts, and google-ai-studio now reaches `ready`
  from the ambient `GEMINI_API_KEY` on the live gateway.
  `TestProviderReconcilerDiscoversAmbientKey` and
  `TestCatalogCredentialEnvironmentPrecedence` hold the behavior.
- The suspected generation-store credential drop does not exist. The Starmap
  payload codec round-trips `Provider.Credentials` completely
  (`EncodeCatalogPayload` → `DecodeCatalogPayload` → `DeepCopyProvider`).
  `TestGenerationRoundTripPreservesCredentialContracts`
  (`internal/catalog/generation_credentials_test.go`) locks this in.

The remaining defect was the evidence half: zero operator-visible detail
when a provider stays unconfigured or a source fails. That is what CP16
ships.

## What shipped

- `CredentialObservation.Detail` and `CredentialStatus.Detail`
  (`json:"detail,omitempty"`) in `internal/providers/state`: a secret-free
  operator diagnostic. Detail changes advance the projection revision.
- Reconciler (`internal/providers/reconciler.go`):
  - `checkedCredentialEnvironment(provider)` builds "checked X, Y, Z" from
    the derived `STARPORT_<PROVIDER>_<FIELD>` name, its `_REFERENCE`
    variant, and the catalog's ambient aliases. Set on every
    `not_configured` observation.
  - `CredentialFailureDetail(err)`: typed source errors render their
    secret-free text; any other error collapses to its classification
    ("credential source is unavailable") so raw internal text never
    reaches an HTTP response.
  - Failure observations carry the safe detail; refresh-retained
    observations carry "refresh failed; kept prior material: <detail>".
- `POST /api/v1/admin/providers/refresh` now returns
  `failures: [{provider_id, reason}]` beside `failure_count`, with the
  classified reason (raw error text stays redacted — existing contract
  test unchanged).
- Console: `operator_credential.detail` in the API type; the provider
  credential panel parses "checked …" detail and renders the authoritative
  env-var list (replacing the naive client-side `<PROVIDER>_API_KEY`
  guess), and shows failure detail beneath the state line.
- `scripts/verify-catalog-performance.sh` gains CPV19 (credential state
  carries operator-facing detail).
