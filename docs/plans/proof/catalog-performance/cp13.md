# CP13 — Composer retool (presets to picker, "+" becomes attachments)

Date: 2026-08-22. Branch: `codex/cp13-composer`.

## What shipped

- `console/src/components/chat/Composer.tsx`: the presets popover is
  gone from the composer — the model picker is the single home for
  presets. The "+" button now owns image attachments: it opens a file
  picker (`accept="image/*"`, up to four files), reads each file as a
  data URL, and renders a chips row with thumbnails and per-chip
  remove buttons above the control bar. The button is capability
  gated: it disables with an explanatory label when the selected
  model does not list `image` in its input modalities
  (`supportsVision`) or when compare mode is active, and pending
  attachments clear when the gate closes.
- `console/src/lib/chatStore.ts`: `ChatMessage` carries
  `images?: string[]` on user turns; `messageContent` builds the
  request shape — a plain string when the turn has no images (legacy
  contract unchanged), OpenAI content parts (`text` +
  `image_url`) when it does.
- `console/src/routes/chat.tsx`: send, retry, and edit all carry the
  turn's attachments through `messageContent`; history replay sends
  prior turns with their images.
- `console/src/components/chat/Messages.tsx`: user turns render their
  attached images as thumbnails above the bubble.
- `internal/providers/connectors/content.go` + fixes in
  `google_base.go` and `anthropic.go`: the live round-trip surfaced a
  gateway defect — both converters did bare `msg.Content.(string)`
  assertions, so any OpenAI-style content-part message panicked the
  Google path and mis-encoded images on the Anthropic path (hardcoded
  `image/jpeg`, whole data URL passed as base64 payload). Both now
  parse content through `ParseMessageContent`; `parseImageDataURL`
  splits data URLs into a real media type and bare payload; Gemini
  gets `inline_data` / `file_data` parts and a system prepend that
  survives an image-first turn; Anthropic gets correct `base64` /
  `url` image sources.
