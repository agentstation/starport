# CP14 — Overhead timing seam + x-starport-overhead-ms header

Date: 2026-08-22. Branch: `codex/cp14-overhead`.

## What shipped

- `internal/execution/overhead.go`: `OverheadTimer` measures gateway-added
  latency as wall time minus accumulated upstream waits. Context helpers
  `WithOverheadTimer` / `OverheadTimerFrom`. Every method is nil-safe, so
  call sites need no guard. `OverheadMS` never reports below zero.
- `internal/proxy/overhead.go`: `OverheadHeader` constant
  (`x-starport-overhead-ms`), `StartOverhead` and `OverheadMS` facades. The
  proxy layer owns the header name; the execution layer owns the timer.
- Upstream marks at the three connector call sites: `connector.Chat`
  (`internal/router/router.go`), `connector.ChatStream` open and every
  `stream.Recv` (`internal/router/execution_adapter.go`,
  `connectorEventStream` carries the timer).
- Persistence: `usage.Record.OverheadMS` (`overhead_ms`, omitempty). Stamped
  in `ProcessChatCompletion`, the stream error path, and
  `usageCaptureStream.finalize`. The store is a JSON blob, so no migration.
- Header wiring: `ChatController.Create` starts the timer;
  `setOverheadHeader` writes the header on non-stream success, non-stream
  error, and before the SSE header flush on streams. Embeddings are
  excluded on purpose: no upstream marks exist there yet, so a header would
  report inflated numbers.
