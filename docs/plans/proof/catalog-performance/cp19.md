### Finding: retry budgets have no operator surface

`router.WithExecutionConfig` was the only writer of `modelRouter.config.Execution`,
and nothing called it, so the router always runs `execution.DefaultConfig()`:
3 attempts, no per-route retry, a 2-minute elapsed budget, and 100 ms
backoff doubling to 2 s. No config field, environment variable, or flag
reaches it.

This is a pre-existing gap, not a regression from the sweep: the option
was never wired to a configuration source, so deleting it removes no
shipped behavior. Recorded here so the campaign does not lose it. Giving
operators a retry-budget surface needs a config struct, environment
tags, validation, defaults, documentation, and a verification condition,
which is a task rather than a cleanup line.

## No capability was lost

Each removal was checked against the live path before deletion, and the
running gateway was then exercised end to end on the CP19 build.

`go build ./...` clean, `go vet ./...` clean, `go test ./...` exit 0
across 40 packages with no failures.

Live acceptance against the local dev gateway on the CP19 binary:

| Path | Evidence |
|---|---|
| `GET /v1/models` | 422 models |
| `GET /api/v1/providers` | 12 providers |
| `GET /api/v1/authors` | 104 authors |
| `POST /v1/chat/completions` | `content: "OK"`, usage `{input 6, output 1, total 124, reasoning 117}` |
| `POST /v1/chat/completions` (stream) | 9 `data:` frames ending in one usage frame |
| HTTP request log | `{"method":"POST","path":"/v1/chat/completions","status":200,"duration":3258.85}` |
| `GET /api/v1/activity` | non-streamed record `latency_ms 3258, routing_ms 3199, overhead_ms 58, attempts 3, cache_status MISS, status ok`; streamed record `latency_ms 1961, ttft_ms 977, overhead_ms 73` |

The activity records are the direct evidence that removing
`TimingMiddleware` and `LoggingMiddleware` cost nothing: latency, TTFT,
routing time, and gateway overhead still populate, because
`usage_capture.go` owns that measurement and `server/logger.go` owns the
HTTP request line. TTFT is present on the streamed record and correctly
absent on the non-streamed ones.

The two empty-content chat responses seen at `max_tokens` 8 and 64 were
the model spending its whole budget on reasoning tokens (61 of 64), not
a gateway defect; the same request at 600 returned `OK`.
