Starport developer experience plan

Status: active · Owner: this plan · Created: 2026-08-09 · Baseline: master @ a62fc289ed59c058013ee0ff5a411dd083e8454c · Proof root: docs/plans/proof/starport-developer-experience/ · Next action: record DX0 proof and publish its pull request

Outcome

Starport gives a developer one tested install, setup, diagnosis, and first-request path. The same release keeps explicit production configuration, renewable cloud credentials, and verified distribution artifacts.

Progress

The status ledger supplies the progress value.

Architecture

Scope

Owns: the Starport default branch, configuration sources, local setup, CLI contracts, provider authentication, Homebrew delivery, developer tools, and current user documentation.

Does not own: provider and model facts. Starmap owns those facts. AgentStation release operations owns Apple and Windows credential procurement.

Non-goals: this plan does not add billing, SSO, a dashboard, new inference protocols, provider aliases, or compatibility paths.

Promotion gate

  • The scope covers every accepted review finding.
  • Each task has observable acceptance criteria.
  • The baseline commit and proof root are exact.
  • The goal block names the repository, branch, and completion gate.
  • The owner asked Codex to activate and execute the plan.

Invariants

  1. Starmap remains the only owner of provider and model facts.
  2. Starport owns inference credential values, refresh, and request placement.
  3. Setup never overwrites an existing configuration or identity store.
  4. Starport never logs or returns a stored secret.
  5. Local secret files use owner-only permissions.
  1. Production keeps environment and secret-manager configuration.
  2. The OpenAI-compatible and OpenRouter-compatible APIs keep their current contracts.
  3. The route plan and attempt budget behavior do not change.
  4. Stable casks point only to verified immutable release artifacts.
  5. New code adds no legacy branch, provider, or storage compatibility path.
