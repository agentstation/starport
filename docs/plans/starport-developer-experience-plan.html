Outcome

A developer runs one command on a clean machine and gets a persistent local gateway on a known port, with no separate initialization step. An operator runs starport serve with explicit configuration and a fixed port that the gateway never changes. Both paths share one storage layout, one key policy, and one documented sequence.

Architecture

Both commands become profiles of one runtime over one storage root. The init command stays for operators who mint the first key separately. The scratch directory becomes an opt-in flag.

Scope

Owns: the standard port and its footprint. First-run initialization inside serve and dev. Persistent dev storage. Bind-before-open and the developer port fallback. The documents, tests, and scripts that pin the first-use sequence.

Does not own: the release tag after the merge (owner action). The README GIF regeneration (README funnel procedure). Changes to starmap/pkg/productpaths (Starmap). The Dockerfile base images (separate change).

Non-goals: a start alias. A port fallback for serve. A check for Windows excluded port ranges. More than one gateway per user on one machine. A --reset flag that deletes shared storage.

Invariants

  1. serve never changes its port. A busy port is an error with the port number in the message.
  2. First-run initialization mints a master key only for the local platform storage root. It runs only when no master key, no Badger store, and no setup transaction exist.
  3. Partial setup state keeps the current error. Configured shared storage keeps the explicit init --configured-storage path.
  4. The first gateway API key prints once, in the terminal of the command that minted it. No later run prints it.
  5. dev binds a loopback address only.
  6. An explicit STARPORT_SERVER_PORT wins over the standard port and disables the developer fallback.
  7. The browser opens only after the gateway listener is bound, and only to the bound address.
  8. When dev falls back, it prints the busy port and the bound port before the console link.
  9. No security default weakens. The master key stays required, the local token stays read-only, and the TLS and JWT paths stay unchanged.
  10. Documents and tests change in the same pull request. cmd/starport/readme_test.go keeps pinning the first-use sequence.
