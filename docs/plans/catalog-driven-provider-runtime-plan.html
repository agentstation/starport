Catalog-driven provider runtime plan

Status: active. Owner: this plan. Created: 2026-08-10.
Baseline: Starport main @ 101c32d. Starmap main @ 7f53767.
Proof root: docs/plans/proof/catalog-driven-provider-runtime/.
Next action: CDP7.1 measures and implements accepted direct secret-source adapters in Starport.

Outcome

Provider YAML and verified evidence define provider, model, and credential metadata in one Starmap catalog generation. Starport builds a complete runtime generation from that catalog, compiled transport and authentication primitives, operator configuration, and credential sources. Each request selects tenant or operator credential material without storing a secret in a connector.

Progress

The status ledger is the progress source.

Architecture

Scope

Owns: Starmap credential metadata, provider YAML migration, and provider and model fact migration. It also owns Starport dynamic provider activation, request credential selection, and runtime replacement.

The plan includes ambient, env:, file:, and cloud default credential sources. It also includes remote catalog consumption, setup, diagnosis, BYOK, tests, documentation, and releases.

Does not own: a new inference protocol. A later protocol plan owns each provider that needs a new wire codec. A later direct-secret-source plan owns an adapter only after evidence records a specific technical, security, licensing, maintenance, architectural, operational, or approved hard-budget blocker.

Non-goals: secret writes, provider-side rotation, generic configuration templates, automatic model approval, compatibility aliases, build-tag release variants, and a shared runtime secret package.

Invariants

  1. Starmap owns provider IDs, model IDs, offerings, prices, limits, capabilities, service endpoints, status facts, and credential metadata.
  2. Starport owns provider inference credential values, tenant selection, runtime policy, request execution, and provider availability.
  3. Catalog-acquisition values never cross into the inference credential plane.
  4. A catalog generation never contains a secret value or secret-store authentication value.
  5. Compiled registries contain transport and authentication primitives, not provider rosters.
  6. A provider needs no Go change when it uses a compiled transport and authentication primitive and its facts fit the typed catalog schema. A new primitive or unsupported wire shape can require Go.
  7. Connectors contain transport state and endpoint bindings. They never contain tenant or operator credential material.
  8. Each request carries an explicit credential selection result into authentication placement.
  9. Credential fallback uses the same attempt budget as route fallback. It cannot create a hidden provider attempt.
  10. Provider model IDs remain exact and opaque from catalog input to the outbound request.
  11. Conventional provider environment names precede derived product aliases during ambient discovery.
  12. The first non-empty ambient value wins. Invalid selected values fail without a lower-priority fallback.
  13. Credential resolution preserves secret bytes. It does not trim, normalize, log, or serialize them.
  14. An explicit secret reference fails closed unless the operator configures a fallback.
  15. The credential layer owns source caching, single-flight resolution, versions, expiry, and lease renewal.
  16. A credential value rotation does not replace a runtime generation.
  17. Query placement requires verified provider evidence. Diagnostics never expose a credential-bearing URL or full query string.
  18. Verified refresh retains the complete last-known-good runtime after any catalog, configuration, source, or connector failure.
  19. Direct breaking changes remove old environment names and provider configuration structures.
  20. One provider claim can populate each canonical fact that its documented semantics entail. It cannot populate facts beyond that entailment. Unknown and false values remain distinct.
  21. Provider IDs, model IDs, author names, family names, and free text cannot create a capability fact.

Dependency and adapter policy

The baseline uses Go 1.26.5 with CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags='-s -w'. Starport is 49,791,138 bytes with 157 modules and 609 compiled packages. Starmap is 36,769,954 bytes with 126 modules and 570 compiled packages.
