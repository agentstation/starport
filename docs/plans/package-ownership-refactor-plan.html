Package Ownership Refactor Plan

Status: active. Owner: this plan. Created: 2026-08-12. Baselines: Starport main@1243849111f5814d0e3418ac7920900fc4a0ea98 and Starmap main@91319bc91422685b5e2937646f7efa5dea2fe371. Proof root: docs/plans/proof/package-ownership-refactor/. Next action: commit POR3, run its pre-PR review, and publish the reviewed Starmap pull request.

Outcome

Starmap and Starport organize internal Go packages by stable product concepts. Each package owns one contract. Its import path communicates the intended owner. Executable architecture tests enforce dependency direction and approved paths. The refactor removes duplicate test authority and unused production surfaces. It preserves public behavior, data schemas, catalog facts, and protocol bytes.

Progress

The status ledger supplies progress.

Architecture

Scope

Owns: internal package paths, package declarations, import aliases, tests, architecture guards, scripts, and related documentation.

Owns: Starmap bootstrap budget classification and YAML-backed OpenAI-compatible provider contracts.

Owns: Starport provider authentication separation and provider HTTP transport simplification.

Owns: provider fixture layout, refresh tooling, package comments, generated package documentation, and stale-path verification.

Does not own: new providers, models, routes, credential backends, storage schemas, or protocol features.

Does not own: model aliases, routing policy, release publication, or unrelated repository cleanup.

Does not own: rewrites of historical reviews, archived proof, or generated local coverage files.

Non-goals: a general ban on compound package names, compatibility packages, forwarding paths, and new dependencies.

Invariants

  1. Starmap remains the only owner of provider, model, offering, and acquisition facts.
  2. Starport remains the owner of inference credentials, runtime state, execution, and protocol adaptation.
  3. Provider YAML remains the authority for provider-specific facts within a compiled transport contract.
  4. No provider roster, model roster, or provider-ID behavior branch enters Starport.
  5. Exact opaque provider model IDs remain unchanged.
  6. Package moves add no compatibility package or forwarding import path.
  1. Durable runtime records, key prefixes, public JSON fields, HTTP routes, and protocol bytes remain unchanged.
  2. Credential values remain absent from logs, errors, state snapshots, URLs, and serialized runtime data.
  3. The execution package owns the total inference attempt deadline.
  4. A hard gate needs an objective, method, unit, limit, owner, consequence, exception, and reopen condition.
  5. Normal Go scheduling applies to ordinary and race tests.
  6. Each product pull request updates its current documentation and verification surfaces.
  7. Historical reviews and archived proof remain unchanged unless a link repair requires an edit.
  8. POR2 may version the internal budget report when its policy schema changes.

Decisions

IDDecisionEvidence and consequenceReopen condition
POR-D01Move sourcepayload to internal/sources/payload.Starmap already owns acquisition sources under internal/sources. Callers import the package as sourcepayload.Reopen if payload processing becomes independent of source input.
POR-D02Replace httpapi with internal/protocol.The child packages own OpenAI and OpenRouter wire contracts. A generic internal/api path does not name that ownership.Reopen if Starport adds a distinct non-protocol API concept.
POR-D03Move provider state to internal/providers/state.The package projects provider runtime state. External callers import it as providerstate.Reopen if provider state becomes a wider runtime state model.
POR-D04Move response cache logic to internal/response/cache.The path separates response semantics from byte-cache storage. Callers use the import alias responsecache.Reopen if response storage and semantic identity gain separate owners.
POR-D05Rename repositorytest to repotest.The familiar repo abbreviation produces the clear call site repotest.Run.Reopen if the harness expands beyond repository contracts.
POR-D06Use bootstrap/{manifest,budget} and test/{catalog,logging,providerfixture}.Bootstrap constructs the embedded fallback artifact that manifest and budget govern. The test children each own one test contract.Reopen if a child gets a second independent owner.
POR-D07Split provider authentication from cloud credential acquisition.providers/auth applies request credentials. credentials/cloudchain gets renewable material.Reopen if the lifecycle contracts converge in production.
POR-D08Delete the standalone Starport httpclient package.Only connectors use its constructor. Delete unused middleware, metrics, debug headers, deprecated fields, and the resulting x/time dependency.Reopen when a second production consumer needs a shared transport contract.
POR-D09Do not enforce a global compound-name ban.Go package guidance favors short names that describe one concept. Architecture tests enforce this plan's approved map.Reopen after a repository naming policy changes.
POR-D10Classify each Starmap catalog limit from evidence.Each limit becomes a ratified hard gate, a report-only review threshold, or deleted policy. An unclassified number cannot reject a release.Reopen when an approved product or distribution objective changes the policy.
POR-D11Store shared provider captures under openai/testdata/providers/{provider}.Fixture metadata supplies explicit provider identity. Embedded YAML supplies endpoint, credential, mapping, and author facts.Reopen when another transport owns the capture.
POR-D12Use one product pull request per POR1 through POR7.A dedicated Starport control branch records ledger and proof updates. Product branches start from current main.Reopen when a task proves mechanically inseparable from its successor.
POR-D13Reject stale paths only on current authority surfaces.Source, tests, scripts, workflows, current docs, and generated package docs must use approved paths. Historical evidence remains exact.Reopen when the repository adopts an archive migration policy.
POR-D14Keep total request deadlines in execution contexts.The connector client owns connection and response-header limits. It has no total timeout that can terminate a healthy stream.Reopen if a production connector caller bypasses execution.

Pull request gate

  1. Commit only the active task and its current documentation.
  2. Run the task verification commands with normal Go scheduling.
  3. Run autoreview --gate pre-pr --mode auto after the work commit.
  4. Resolve every accepted review finding and rerun affected commands.
  5. Set POR_HEAD_SHA=$(git rev-parse HEAD) and publish the task pull request.
  6. Set POR_PR_URL=$(gh pr view --json url --jq .url).
  7. Run gh pr checks "$POR_PR_URL" --watch --fail-fast.
  8. Confirm gh pr view "$POR_PR_URL" --json headRefOid --jq .headRefOid equals $POR_HEAD_SHA.
  9. For a Starport task, merge with gh pr merge "$POR_PR_URL" --squash --match-head-commit "$POR_HEAD_SHA".
  10. For a Starmap task, merge with gh pr merge "$POR_PR_URL" --merge --match-head-commit "$POR_HEAD_SHA".
  11. Switch the product worktree to main and run git pull --ff-only origin main.
  12. Record local results, hosted checks, pull request, head, merge commit, and proof path in the control ledger.
