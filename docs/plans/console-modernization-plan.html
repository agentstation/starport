Starport console modernization

Status: active · Owner: this plan · Created: 2026-08-21 · Baseline: main @ 2818e74 · Proof root: proof/console-modernization/ · Next action: execute CM7 (usage with charts)

Outcome

The Starport console is a React SPA built on the modern trusted stack (Vite 8, React 19, TypeScript, Tailwind 4, shadcn/ui on Base UI, TanStack Router/Query/Table/Virtual, Streamdown) and styled by the repository design system in DESIGN.md. Every page follows the design laws, the chat composer carries the model picker in the bottom input bar, and the legacy hand-rolled JS console is deleted. The binary still embeds the whole console and works air-gapped.

Progress

Progress appears here when the page loads. The status ledger below is the source of truth.

Architecture

Scope

Owns: the frontend workspace under console/, the embed and serve contract in internal/console, the design system document DESIGN.md, the rebuild of all eight console pages, the chat composer redesign with the bottom-bar model picker, comparison mode, the command palette, the build wiring (Makefile, CI), and the deletion of the legacy static console.

Does not own: gateway backend behavior. The recorded backend defects (provider-pinned routing, credential fallback, catalog ID projection, budget middleware placement) belong to a future backend plan. Starmap catalog facts belong to Starmap.

Non-goals: SSR or TanStack Start; a public marketing site; new gateway API endpoints beyond what pages already consume; auth changes; mobile-native apps.

Invariants

  1. The console works air-gapped: no runtime CDN for scripts, styles, or fonts. Everything ships inside the binary.
  2. DESIGN.md governs all visual decisions. A new pattern lands in DESIGN.md before its first use.
  3. Every page ships dark and light themes together.
  4. Model and provider facts come from the gateway API (one Starmap snapshot). The frontend holds no model lists or price defaults.
  5. The OpenRouter parity capabilities guarded by scripts/verify-openrouter-parity.sh survive the rebuild. The cutover re-points its conditions to the new paths; it never deletes a condition.
  6. go build ./... succeeds without Node when console/dist is absent; the binary then serves a plain "console not built" notice. Release binaries always contain the built console.
  7. Main stays shippable: the legacy console keeps serving until the CM14 cutover task flips the default.
