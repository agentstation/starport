Files API

Status: proposed · Owner: this plan · Created: 2026-08-26 · Baseline: FIL0 pins the repository · Proof root: docs/proof/files-api/ · Next action: MOD16 promotes this plan

Outcome

A caller uploads a file to Starport, lists it, reads it back, and deletes it. The bytes live in a blob store that a deployment points at a local directory or an object store, and the record lives beside every other tenant record. A later request references the file by identifier instead of carrying its bytes again.

Progress

Progress appears here when the page loads. The status ledger below is the source of truth.

Architecture

The key store keeps its job. It holds small records that a transaction touches. Large opaque bytes move to a seam built for them.

Scope

Owns, the storage seam. The package internal/blob, its contract, its contract test, its filesystem backend, and its object store backend. The rule that the key store holds a record and never the bytes.

Owns, the caller surface. The tenant-scoped file record and its repository. Five routes under /v1/files. The files:write and files:read scopes. The multipart upload path and the retention window.

Owns, the policy. The per-tenant stored byte limit in internal/limits. The deletion path. The reference that lets a chat request name a stored file instead of carrying its bytes.

Does not own. Text extraction from a stored document, which the document parser plan owns. The asynchronous job record and its states, which the async media jobs plan owns. That plan consumes this seam for its generated assets, so this plan lands first.

Non-goals. A batch API, which needs a job seam this plan does not build. A fine-tuning or assistants purpose, because Starport serves neither. A public download URL, because a signed public link is a distribution decision the owner has not made.

Invariants

IDInvariantReason
F1The key store holds a file record. It never holds file bytes.A key store value moves through transactions, batches, and a compare-and-swap path built for small records. A multi-megabyte value would make each of those operations expensive.
F2One contract test runs against every backend, and a backend ships only when it passes.Two backends behind one interface drift the moment one of them answers a case the other does not.
F3The filesystem backend is the default. A deployment selects the object store through configuration alone.A developer starts Starport with no external dependency, and an operator changes one setting to move to shared storage.
F4A file belongs to exactly one tenant. A read or a delete across tenants fails as a not-found result.A cross-tenant read leaks caller data. Reporting a refusal instead of a not-found result would confirm that the file exists.
F5A blob key is opaque. It carries no filename, no caller path, and no tenant secret.A key derived from a filename lets a caller reach another record through a traversal sequence.
F6Every stored file states a retention window and has a deletion path.Storage that only grows becomes an unbounded cost and an unbounded liability.
F7Stored bytes count against a per-tenant limit, checked before the write completes.A check after the write has already spent the disk it meant to protect.

FIL1 The blob seam

Problem. The package internal/storage holds one byte-valued key store with transactions, batches, and a compare-and-swap path. Those operations suit small records. A multi-megabyte value would move through every one of them, so file bytes need their own seam.

Seam. internal/blob and its contract test.

  1. Define the contract with put, get, stat, and delete, over streams.
  2. Make a failed put leave no readable object at its key.
  3. Make the key opaque, and reject any key holding a path separator.
  4. Write one contract test that a backend must pass.
  5. Implement the filesystem backend under a configured root directory.
  6. Register the package in the import graph test with its allowed imports.

Acceptance, FIL-V01 to FIL-V03. The contract test passes against the filesystem backend. It covers put, get, stat, delete, a missing key, an overwrite, and an interrupted put. A second test asserts that a key holding a path separator fails before any write. A third test asserts that TestImportGraphArchitecture names the package and refuses an import outside its allowlist.

Fail-before. The package does not exist.

Verification. go test ./internal/blob/... ./internal/architecture/.... Then bash scripts/verify-package-layout.sh.

FIL2 The object store backend

Problem. A filesystem backend serves one node. A deployment that runs two Starport processes would give a caller a file on one node and a not-found result on the other. The owner asked for both backends, so the object store must satisfy the same contract with no interface change.

Seam. internal/blob, internal/config, and internal/app.

  1. Implement the object store backend against the FIL1 contract.
  2. Run the FIL1 contract test against it without a new case.
  3. Select the backend from configuration, with the filesystem as the default.
  4. Refuse startup when the object store configuration is incomplete.
  5. Report the selected backend once at startup.
  6. Keep the object store credentials out of every log line and every error.

Acceptance, FIL-V04 to FIL-V06. The FIL1 contract test runs against both backends from one table. A second test asserts that an absent configuration selects the filesystem backend. A third test asserts that an incomplete object store configuration refuses startup with an error that names no credential.

Fail-before. Only one backend exists.

Verification. go test ./internal/blob/... ./internal/config/... ./internal/app/.... Then bash scripts/verify-v1-architecture.sh.

FIL3 The file record

Problem. Bytes alone answer no caller question. A caller asks for a filename, a size, a purpose, a creation time, and an expiry. Two stores also create an orphan case, because a crash between the two writes can leave bytes that no record names. The blob contract lists no keys, so a sweep can never find those bytes.

Seam. internal/files and its repository.

  1. Define the record with an identifier, a tenant, a filename, and a size.
  2. Give the record a purpose, a creation time, and an expiry time.
  3. Hold the blob key inside the record alone.
  4. Follow the repository pattern that internal/presets uses, and register the package in the import graph test.
  5. Write a pending record first, then the bytes, then commit the record.
  6. Sweep a pending record that never committed, and delete the bytes it names.

Acceptance, FIL-V07 to FIL-V09. A test asserts that a read for another tenant returns a not-found result rather than a refusal. A second test asserts that a crash before the commit leaves no reachable file, and that the sweep deletes the bytes the pending record names. A third test asserts that the record exposes no blob key through its public accessors.

Fail-before. No file record type exists.

Verification. go test ./internal/files/... ./internal/blob/... ./internal/architecture/.... Then bash scripts/verify-dependency-direction.sh.

FIL4 The routes and the scopes

Problem. A caller reaches no file route today. The request size limit bounds a JSON body, and an upload needs a multipart body with its own bound. The anonymous identity at DefaultAnonymousScopes in internal/identity/anonymous.go carries a fixed scope list, so a deployment with authentication disabled would reach a new route with no scope.

Seam. internal/server, internal/protocol/openai, and internal/identity.

  1. Register POST /v1/files, GET /v1/files, GET /v1/files/{file_id}, DELETE /v1/files/{file_id}, and GET /v1/files/{file_id}/content.
  2. Guard the writing routes with files:write and the reading routes with files:read.
  3. Decode a multipart upload and stream it to the blob store.
  4. Refuse a purpose outside the FIL0 list with a typed error.
  5. Encode the file object exactly as FIL0 recorded it.
  6. Add both scopes to the anonymous list, the route guards, and the operator guide.

Acceptance, FIL-V10 to FIL-V13. A server test uploads, lists, retrieves, reads content, and deletes one file. A second test asserts that a key holding only files:read cannot upload. A third test asserts that an upload larger than the configured bound fails without writing a partial blob. A fourth test asserts that the encoded object carries every recorded field.

Fail-before. Each route returns 404.

Verification. go test ./internal/server/... ./internal/protocol/... ./internal/identity/.... Then bash scripts/verify-auth-onboarding.sh.

FIL5 Retention and deletion

Problem. Invariant F6 requires a stated window and a deletion path. A delete touches two stores, and a partial delete leaves either unreachable bytes or a record pointing at nothing. An expiry that nothing enforces is a comment rather than a window.

Seam. internal/files, internal/blob, and internal/app.

  1. Give every record a retention window, and let an upload shorten it.
  2. Mark the record deleting, delete the bytes, then delete the record.
  3. Start the sweep in internal/app, on a bounded ticker.
  4. Sweep every expired record and every abandoned pending record.
  5. Report a retrieval of an expired file as a not-found result.
  6. Record each sweep result where an operator can read it.

Acceptance, FIL-V14 and FIL-V15. A test asserts that a delete removes both the record and the bytes. A second test asserts that a failure during a delete leaves no reachable record and no unreachable bytes. A third test asserts that an expired file reads as not found before the sweep runs.

Fail-before. No record carries an expiry.

Verification. go test ./internal/files/... ./internal/blob/.... Then go test ./....

FIL6 The stored byte limit

Problem. The package internal/limits bounds requests, spend, and tokens. It bounds no stored bytes, so one tenant could fill the disk or the bucket. Invariant F7 wants the check before the write completes, because a check afterward has already spent the storage.

Seam. internal/limits and internal/tenant.

  1. Add a stored byte bound to the limit vocabulary.
  2. Track the stored byte total for each tenant in an atomic counter.
  3. Reserve the byte count with one increment before the write starts.
  4. Release the reservation with a decrement when the write fails.
  5. Lower the total when a delete or a sweep removes bytes.
  6. Give a gateway API key the same bound, and report it on the tenant record.

Acceptance, FIL-V16 and FIL-V17. A test asserts that an upload passing the bound fails and leaves no partial blob. A second test asserts that a delete lowers the total by the file size. A third test asserts that two concurrent uploads cannot both pass a bound that admits one.

Fail-before. The limit vocabulary names no byte bound.

Verification. go test ./internal/limits/... ./internal/tenant/... ./internal/files/.... Then bash scripts/benchmark-overhead.sh.

FIL7 Reference a stored file

Problem. Storage that no request can read serves nobody. A caller that uploaded a document once still resends its bytes on every turn, which spends the request bound the model modalities plan raised. A reference removes that cost.

Seam. internal/inference, internal/protocol/openai, internal/protocol/openrouter, internal/proxy, internal/response/cache, and the internal/files and internal/blob readers that FIL1 to FIL3 build.

  1. Let a document content part name a stored file identifier.
  2. Resolve the identifier inside the owning tenant, and refuse another tenant identifier as a not-found result.
  3. Keep the inline bytes path working, unchanged.
  4. Treat a stored file reference as cache-eligible, and put its identifier in the cache key.
  5. Refuse a request that names both a file identifier and inline bytes.
  6. Read the bytes once for each request, never once for each attempt.

Acceptance, FIL-V18 and FIL-V19. A test asserts that a stored file reaches the provider as the same bytes an inline request sends. A second test asserts that a file belonging to another tenant produces a not-found result before any provider call. A third test asserts that a retry reads the bytes once. A fourth test asserts that two requests naming different file identifiers produce different cache keys.

Fail-before. A content part cannot name a stored file.

Verification. go test ./internal/inference/... ./internal/protocol/... ./internal/proxy/.... Then bash scripts/verify-openrouter-parity.sh.
