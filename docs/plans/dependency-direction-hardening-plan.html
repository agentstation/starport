Outcome

Stable domain and use-case packages depend only on owned contracts. Starmap's public catalog tree has no dependency on repository-private implementation packages. Starport's gateway use cases depend on cache and provider-runtime contracts, and Starmap acquisition policy stays inside Starport's catalog seam. Executable import rules prevent each reversed dependency from returning.

Scope

Owns: Starmap catalog authority, bounded payload decoding, catalog resource policy, and explicit embedded composition. It also owns Starport proxy contracts, catalog refresh composition, architecture guards, affected documents, and two implementation pull requests.

Does not own: provider or model facts, schemas, release tags, storage backends, routing policy, protocol behavior, credential behavior, or an external catalog service. Separate future plans own those changes.

Non-goals: compatibility wrappers, a broad catalog type split, Starport local-acquisition removal, runtime-lease replacement, package renames without ownership change, new dependencies, and release publication.

Invariants

  1. Starmap keeps one authority table for immutable definition derivation and reconciliation.
  2. Fixed catalog inputs keep identical catalog, payload, manifest, artifact, and remote bytes.
  3. Starmap acquisition remains explicit and keeps its current credential plane.
  4. Starport request leases retain one matching catalog snapshot and connector generation.
  1. Starport keeps inference credentials separate from Starmap acquisition credentials.
  2. Gateway HTTP, protocol, routing, cache, and provider behavior do not change.
  3. No task adds a module dependency, wrapper, schema, protocol, provider fact, or model fact.
  4. All changes target main only through pull requests.

Decisions

IDDecision and evidenceConsequenceReopen condition
D1Keep pkg/catalogs as one public domain tree. Recent ownership work and file sizes support coherent ownership.The campaign repairs dependency direction without a broad type split.A measured consumer or change cluster cannot state a catalog-tree contract.
D2Expose authority as pkg/catalogs/authority. It has two real consumers and one policy invariant.Read-view derivation and reconciliation share one catalog-owned policy.One consumer becomes the sole policy owner.

Rejected designs

  • Split every Starmap catalog type: the evidence shows reverse imports, not incoherent type ownership.
  • Remove local acquisition from Starport: the evidence supports an import boundary, not a product behavior break.
  • Replace request runtime leases: current contract tests prove generation retention and connector draining.
  • Keep old package aliases: pre-v1 aliases would retain two authorities.
  • Rename composition roots: their expected high fanout is not the measured defect.
