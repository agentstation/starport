Outcome

Starport records every inference request with tokens, provider, latency, and Starmap-derived cost, and serves that history through an activity API and a console usage page. The console shows what each catalog refresh changed and how fresh the catalog is. A request can name a stored preset, order providers by price or latency, and cap price. An operator can give a key model limits, an expiry, and spend and token budgets that the gateway enforces. Every surface degrades loudly: a missing price, a stale catalog, or an exhausted budget is visible, never silent.

Scope

Owns: per-request usage recording and cost computation, the activity and metrics API, catalog freshness and generation-diff surfaces, preset management and request-side preset references, completion of the OpenRouter provider preference object, per-key limits and budgets, and the console pages for usage, freshness, presets, routing preferences, budgets, and side-by-side chat comparison.

Does not own: provider, model, price, or quantization facts (Starmap owns facts; a Starmap plan owns adding data-policy or quantization facts); SSO, RBAC, orgs, or any tenancy above the API key (a future enterprise-identity plan); OpenTelemetry export and webhooks (a future observability plan); billing, invoicing, or a credits ledger (a future commercial plan); PR #125 merge (owner decision).

Non-goals: SQL storage, WebSocket log streaming, moderation, compatibility paths or legacy storage prefixes, and provider connector additions.

Decisions

IDDecisionRe-open condition
D1Usage records live in the KV store under usage:v1: with time-encoded keys (usage:v1:key:<b64 keyID>:ts:<20-digit zero-padded unix-nanos>:<requestID>) plus atomic aggregate counters for budgets. No SQL. Retention via TTL, default 30 days, configurable.A released deployment needs cross-key time-range queries the scan cannot serve.
D2Cost is computed at request completion from the request-scoped RoutableSnapshot.Offering pricing (input, output, reasoning, cache read/write). A missing price yields an absent cost plus a recorded reason — never zero.Starmap changes the pricing schema.
D3Documented OpenRouter provider fields Starport cannot yet enforce (quantizations, data_collection, zdr, require_parameters, experimental) are accepted and recorded as unenforced in the response metadata rather than rejected — a drop-in replacement must not 400 on documented fields. Enforcement arrives when Starmap owns the backing facts.Starmap publishes data-policy or quantization facts.
D4Variants map to routing policy: :floor → price sort, :nitro → latency sort (Starport measures latency, not throughput; deviation documented), :free → only zero-price offerings.Starport gains a throughput measurement.
D5Preset config is a typed subset — model, models, provider preferences, system prompt, and sampling parameter overrides — referenced by "model": "@preset/<name>" or a preset body field, matching OpenRouter semantics. Request-supplied fields win over preset fields.OpenRouter changes preset semantics.
D6Budgets enforce from local aggregates in fixed UTC windows (daily, weekly, monthly). Spend counts in integer nano-USD. Exceeded budget → 402 ErrInsufficientQuota. A storage read error allows the request and logs an error: local-first availability wins over enforcement.An operator asks for fail-closed enforcement.
D7The plan verifier scripts/verify-openrouter-parity.sh joins the required evidence list in CLAUDE.md at ORP0 and CI at ORP13, honoring the repository rule that every verify gate belongs to CI, the list, or both.—

Invariants

  1. Starmap remains the only source of provider, model, and price facts. No local price tables, provider switches, or model lists.
  2. Usage recording never blocks, delays, or fails an inference request. Capture is best-effort; a capture failure logs and drops.
  3. Costs and freshness degrade loudly. A missing price, an unpriced route, or a stale catalog is surfaced with a reason, never rendered as zero or fresh.
  4. Tenant isolation holds: a non-admin key reads only its own activity; the response cache and BYOK scoping rules do not weaken.
  5. New storage namespaces are versioned (usage:v1:); no legacy prefixes or compatibility paths.
  6. OpenRouter wire compatibility does not regress: the pinned Python, TypeScript, and Go SDK gates stay green, and documented OpenRouter request fields never 400.
  7. All changes reach main through pull requests with the required evidence checks green.
